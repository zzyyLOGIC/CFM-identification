# 识别执行层：职责、方法合同与迁移边界

当前名称及操作／实现的对应见[方法标识](METHOD_IDENTITIES_ZH.md)。下文四批记录说明原有执行整理；其中历史 R 名称只用于追溯原生实现，现用共同计划已使用语义标识。

## 目标

六项属性描述研究问题；方法通过自己的条件与信息要求证明结论。八种共同读取是现有适配器，不是穷尽、互斥的理论分类，也不是所有算法必须经过的八个节点。

从维护角度，将执行职责分开：

1. **目标与研究模型**：固定目标、评价人群、方向、权重、时期／背景、全部已知信息及采用的科学条件。
2. **方法合同与候选计划**：登记接受的目标操作、原生合同、求解和验证函数；候选资格不代表适用性通过。
3. **审核与原生构造**：核对来源及科学决定，构造当前原生合同。未审核不能进入计算。
4. **计算与证据核验**：调用已有数学实现；核对原输入、返回目标、公式／界限及相应证据。
5. **结果汇总与交接**：保留各方法结果和停止原因；按当前权限交接，不替模型选择更强假设。

这些职责是工程设计，不声称来自文献规定的五层架构。当前 InternalStudy 总视图仍有只读部分；执行已经使用 PolicyQuestion、LocalQuestion 等类型化目标子集，不能把展示模型直接作为全库执行合同。

```mermaid
flowchart LR
    Q[明确的目标、信息与条件] --> P[准备候选方法计划]
    P --> A[核对来源与科学决定]
    A --> C[构造原生规格并检查适用条件]
    C --> K[调用原有求解实现]
    K --> V[绑定本次输入并核验证据]
    V --> R[公式、界限或明确的停止原因]
```

候选可以有多个，不是每个研究只能归入一个格子。未通过某方法的条件，只说明该方法当前不能给出结论；不能直接据此宣布数学上不可识别。

## 理论与工程依据

| 依据 | 支持的设计判断 | 不据此宣称 |
| --- | --- | --- |
| [Aronow 与 Samii：设计、暴露与目标](https://arxiv.org/abs/1305.6156) | 目标、分配机制和暴露分别表达，方法核查它们的组合 | 我们的 D/E 编号或任意组合均有文献保证 |
| [Sävje：区分暴露定义与假设](https://arxiv.org/abs/2103.06471) | 不能把局部目标定义自动变成充分性批准；方法合同应明确两者 | 所有暴露效应都需要相同假设 |
| [Shpitser 与 Pearl：联合干预分布识别](https://cdn.aaai.org/AAAI/2006/AAAI06-191.pdf) | 模型、已有分布、目标与识别算法分离；图路线保留自身语义 | 图 ID 的完备性就是整个项目的完备性 |
| [Duarte 等：离散模型自动求界](https://arxiv.org/abs/2109.13471) | 在完整允许模型中直接求目标范围；POINT/PARTIAL 是数学结果 | 本项目已实现其一般多项式优化算法 |
| [DoWhy 官方识别接口](https://www.pywhy.org/dowhy/v0.14/dowhy.causal_identifier.html) | 目标、识别算法和估计可以使用不同对象与接口 | 它的估计诊断等同于本库的数学证书验证 |

阅读范围：上述论文的目标／算法定义及摘要、官方 API 说明；不是重新审计各篇完整证明。目录层数、函数名、模块边界均由本项目选择。

| 随机化局部效应 | LocalQuestion，带方向的局部对比 | 第二批；共享局部方法绑定、调用及证据检查，保留具名效应与反向线性组合证书 |
| 单个局部均值 | 单节点、单状态均值 | 第二批；共享局部方法绑定和调用，仍使用单端原生输入，不制造第二端 |
| 有限政策混合 | 完整政策及其选择概率 | 第四批；共享有限政策方法绑定与业务结果核验，保留政策分布目标及逐分量证明 |
| 观察性政策 | ObservationalPolicyQuestion，固定背景 | 第三批；共享观察性方法绑定及调用，完整安排和条件均值签名的科学合同仍分别核对 |
| 观察性局部效应 | ObservationalEffectQuestion及三种平均／调整语义 | 第三批；方法必须匹配平均方式和总体算子，分别保留三种原生构造及科学许可 |
| DAG | 干预分布及图模型 | 第四批；读取、业务分派和研究登记共用图方法合同，执行复用原研究流程；保留图合同和验证器 |
| 普通 ATE／Manski、IV、一般图 ID | 各自专用目标和模型 | 继续使用原入口；不能由八个读取类别推断其不可达或未实现 |

## 第一批的可执行整理

policy_methods.py 统一维护固定政策均值／差值的具体方法合同，包括：目标操作、执行策略、对应原生方法、生产函数和重放函数。capability_registry 的这两组绑定从同一合同取得，执行适配器也使用同一合同，避免“登记一份、实际 if/else 又写一份”。

policy_execution.py 只复用原生求解和验证调用，集中有限均值盒的输入不变性、证书不变性及重放检查。它不读取中文、不生成科学批准、不选择更强模型。

这里覆盖 5 个单政策方法绑定和 6 个差值方法绑定，包含原生方法的组合，不代表新增 11 条定理。均值顺序的方法已统一登记，但其审核、构造与提交仍委托原专用实现；条件目录仍引用原生要求，本批没有新增一套平行的科学条件判定器。

| 执行策略 | 语义 | 保留的边界 |
| --- | --- | --- |
| 原生政策 POINT | 对单个完整政策使用已批准的 R1b 或 R2 | 原生支持、充分性及信息检查不变 |
| 已识别端点的差值组合 | 同研究下两个同方法端点的有向组合 | 两端输入、方向、共同模型和组合证明都须核验 |
| 联合有限模型 | 直接求完整目标的最小／最大值 | 不先相减两个独立区间；未知均值可以在差值中抵消 |
| 均值顺序模型 | 在含已采用顺序限制的共同模型中求界 | 保留原专用审核、可行性和对偶证书，不降格为无顺序模型 |

这些策略描述如何执行，不是新的因果效应类别。方法合同只匹配当前已声明目标；原读取器仍负责准备候选，原审核及原生判定仍有最终约束力。本批没有完成全库统一的属性规划器。

## 第二批：随机化局部均值与效应

`local_methods.py` 统一登记两种既有操作：单个节点／状态均值，以及两状态的有向比较。直接、同伴、局部总效应描述哪些坐标改变，仍共用 R1a 的既有均值证明与组合能力，不增加三套平行定理登记。

`local_execution.py` 共用原生调用和输入／证据不变性检查。原适配器继续审核来源、科学条件、评价名单、相减方向、剩余安排的平均方式，并检查返回的目标和所用路线。先完成这些核对，再核验证据；不能只核验后端返回对象自身携带的问题。

| 目标与方向 | 既有原生调用 | 保留的边界 |
| --- | --- | --- |
| 单个节点在单状态下的均值 | `ArmInquiryV21` | 不调用效应批次，不补第二端，不把均值变成差值 |
| 直接／同伴／局部总效应 | 原生批次与 `EffectsInquiryV21` | 两端及权重明确，剩余安排按原设计条件平均；具名效应证书原样保留 |
| 本人状态反向的直接／局部总效应 | 原生线性组合与对象型重放 | 保留原有带符号项与 `CUSTOM_LINEAR` 证书；不交换用户两端，也不在显示层简单取负 |

原有 `_native_payload` 证据快照提取到 `native_evidence.payload`，内容编码不变；旧导入保留为同一函数的别名。单均值、效应和同文件的其他既有实现可复用快照。观察性效应和有限政策混合另有各自的方法合同，不归入局部随机化效应。

原条件检查继续决定适用性，包括必要总体信息、随机化、一致性、处理前固定网络、均值存在、支持及各设计专用前提。单个局部状态与两端对比仍使用不同原生目标类型；未审定条件不因两类代码共享而获得批准。

## 第三批：观察性网络方法

`observational_methods.py` 为两个固定政策方法与三个局部效应方法维护共同函数绑定。两政策方法的选择保留原有支持和充分性检查；三局部方法分别绑定已明确的平均方式。总体信息算子的对应继续复用 `research_spec_observational_adapters` 的既有登记，不维护第二份信息分类。

| 目标／方法 | 必须保留的总体信息与条件区别 |
| --- | --- |
| 完整安排政策均值 | 固定 W 下的完整正概率安排表及所需结果条件均值；完整处理向量条件交换性 |
| 条件均值签名政策均值 | 同一 W、总体来源和条件交换性；另行审核全安排、评价对象范围内的条件均值充分性及签名支持 |
| 按实际分配律平均的局部效应 | 有限安排表、已声明因子分解的总体律或混合总体律；保留完整向量交换性，不推定暴露充分性 |
| 共同分层调整的局部效应 | 处理前 B 的总体质量、各层处理律及条件结果均值；单独的暴露充分性和给定 B、W 的暴露层条件均值交换性 |
| 本人与邻居特征调整的局部效应 | 处理前特征剖面及其总体质量、剖面内处理律或显式混合律、C_i 对应结果均值；单独的暴露充分性与局部特征条件均值交换性 |

上表只列区别；一致性、处理前网络、均值存在、作用范围和支持等原要求继续保留。完整政策两路线不是两个不同的目标类型，而是同一政策目标可能使用的不同证明方法。三种局部平均则是目标含义的区别，不能为了某条方法可运行而互换。

共同的调用生命周期提取到 `native_outcome_execution.py`：计算前保存输入指纹、计算后检查输入未变、按原验证器重放并检查证据未变。随机化局部入口也调用这一实现。每个适配器仍在重放之前核对实际返回的目标、路线及科学输入；原有两种指纹编码分别传入，既有证书和审核摘要不重编码。

该公共实现仅用于返回原生业务结果、重放返回布尔值的调用。反向局部线性证书的重放返回对象，政策直接原生证明、联合求界、均值顺序和图证据也各有合同，不能强行套用。源信息不完整、额外限制、科学条件待定／不采用、未审核和旧审核失效的停止规则均保持。

## 第四批：有限政策混合、DAG 与专用入口收尾

`finite_policy_methods.py` 绑定已有有限政策均值操作、R1b 分量路线、原生计算和重放函数。适配器先按每个完整政策核验，再保留用户给定的全部概率组合；最终结果同时核对组成政策和概率。概率错误不自动归一化，分量缺支持不自动改用 R2 或 PARTIAL。分量及最终结果共用 `native_outcome_execution` 的输入与证据不变性检查；政策分布仍使用原 `FinitePolicyInquiryV21`，不压成一个 `PolicyQuestion`。

`dag_methods.py` 集中经典后门、指定调整集和经典前门的目标操作、规格、审核类型、准备函数、适配器和版本。共同业务登记、研究登记和原 `dag_business.route_contract` 从同一处取得绑定；旧函数及序列化版本保留。DAG 执行已经通过 `research_route_workflow.run_route` 完成原生审核、计算和证据检查，因此继续复用这条流程，没有再造一份图执行器。业务分派继续核对全部候选的审核，并针对本次具体问题再次核验交付的公式和证书。

**八种共同业务读取均已消除方法绑定的重复维护；这不等于全库统一为一种目标或一种证明。** 目标构造仍是五类属性化目标和三类专用目标，专用数学入口也继续可用。

| 保留的入口 | 执行与证据责任 | 保留原因 |
| --- | --- | --- |
| 普通 ATE、单组 ATE、二元 Manski | 原总体引擎及验证器；默认文本另有 `population_ate_entry` 来源与科学审核 | 目标、总体信息、均值存在和额外限制有自己的合同，不能改成网络臂 |
| 二元 IV | `iv_research_adapter`、`research_route_workflow` 及 IV 验证器 | LATE 与总体 ATE 的条件、结论及证据不同，不以某个 DAG 方法失败作为准入 |
| 一般图 ID | `dag_id_route` 及图 ID 验证／见证 | 一般算法与三个充分方法的适用域和失败含义不同；不偷偷追加为业务回退 |
| 均值顺序 | `mean_order` 专用审核、求界及原始／对偶证据 | 虽已共享政策目标和方法登记，不能省略顺序限制或混入无约束均值盒 |
| 批量、任意线性、多目标与观察性成对比较 | 原生操作 `batch`、`linear`、`effects`、`r3_pair` | 同一批的来源、权重、多目标和证书关系均须保留 |
| 支持诊断、旧证书比对、方法要求查询 | `signature_support`、`quota_support`、`legacy_bridge`、`legacy_compare`、`requirements` | 诊断与兼容操作不等于另一类识别结论 |

本地收尾对照还执行了 26 份原生规格，覆盖登记的 12 类原生操作和 6 条研究路线，包括审核前阻断和审核后完整结果。它验证已有入口的兼容性，不宣称任意自然语言都已能自动到达所有路线。

## 不能因重构改变的语义

- **完整目标优先。** 不能要求差值的两个均值各自可识别；联合模型允许抵消，仍须直接核验整体目标。
- **完整条件保留。** 未使用的已声明限制不能被删除。当前额外限制阻断策略不变；将来若允许更弱模型下的证明复用，必须单独核对模型包含关系、相容性及结论类型。
- **sharp 不自动继承。** 忽略额外限制可能仍给出外界，但不能声称是原问题的最紧界。
- **方法之间不自动换假设。** R1b失败不能添加充分性转 R2；POINT失败不能默认转 PARTIAL。
- **只比较同一问题。** 不同目标、人群、背景或科学模型下的结果不按“POINT优先”混选。
- **审核先于计算。** 所有计划分支的审核完成后才能构造并调用数学后端；描述目录不授予权限。
- **不同证据保留不同含义。** 同实现重算、支持核对、图推导核验、端点／对偶证据继续分开说明。

## 扩展规则

新增设计或暴露时，优先扩展其概率／映射组件，并逐方法明确支持条件。新增方法时提供目标操作、原生合同、生产和验证函数，再接入可达的读取适配。新增组合仍需要数学依据及必要检查；代码复用不是组合正确性的证明。

维护位置按责任区分：

| 要修改的内容 | 当前维护位置 |
| --- | --- |
| 单政策或差值的含义、两端及评价范围 | `research_spec_policy` 的 `PolicyQuestion` 与 `research_spec_policy_adapters` |
| 随机化两状态比较、方向与条件平均 | `research_spec_local` 的 `LocalQuestion` 与 `research_spec_local_adapters`；单均值仍保留原单端构造 |
| 政策方法接受什么操作，使用哪个求解／验证函数 | `policy_methods` |
| 单局部均值／局部比较使用哪些原生函数 | `local_methods` |
| 观察性目标与平均方式、方法函数对应 | `research_spec_observational`、其适配器及 `observational_methods` |
| 有限政策分布及其组成政策的函数绑定 | `finite_policy_methods`；原目标、概率及分量构造仍由 `network_extended_dispatch` 维护 |
| 三种充分 DAG 方法的原生规格与适配器对应 | `dag_methods`；读取解释仍由 `dag_business` 负责 |
| 事实是否齐全、计划与科学条件审核、原生输入构造 | `network_policy_dispatch`、`network_contrast_dispatch` 及现有专用适配器 |
| 原生调用、有限模型输入／证书不变性 | `policy_execution` |
| 局部调用与批次、输入／证据不变性 | `local_execution`；既有快照编码由 `native_evidence` 共用 |
| 随机化局部、观察性及有限混合业务结果的调用、布尔重放生命周期 | `native_outcome_execution`；目标及科学输入核对仍属于各自适配器 |
| 图、IV 与均值顺序的类型化研究审核／执行 | 原 `research_route_workflow`；保留各适配器和专用证明合同 |
| 具体定理条件、公式与求界算法 | 原生合同、求解器和验证器；本批没有修改 |
| 对外方法条件说明、入口清单 | `method_catalog`、`capability_registry`；不能另写一套批准逻辑 |

第一批验收使用改造前冻结的完整计划、结果、证书及未审核停止结果，逐值比较；另检查错误方法、操作不匹配、单端缺项、额外限制、陈旧审核、篡改证书及联合目标抵消。此类结构等价验收不代表真实 LLM 的首答准确率。

此前四批维持旧协议。本轮方法命名迁移后的新计划使用 semantic-methods-1；D/E、数学合同及原生证书保持原样，旧计划不得改名后直接复用批准。老入口是兼容边界，不另设一套可以绕过审核的公开执行 API。
