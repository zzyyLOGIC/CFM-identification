# 默认入口与材料交接

默认网页先取得模型原答，再尝试本地核验。如果原答仅被保留、尚无证书、没有明确冲突或待答追问，后台继续使用现有的目标读取、来源审核、事实读取和数学执行流程。原答单独存档，既不作为业务证据，也不替代科学条件确认。

这是入口承接，不是新增识别定理，也不表示模型原答已经正确。只有原求解器给出结论且证书重放通过，才显示经过核验的识别结果。需要补充信息时停止追问；尚未决定或不采用的条件不能由后台批准。

## 运行记录与兼容

- 自动继续仅用于 `reading_mode=direct_verify` 且 `automatic_review=true`。网页已启用此选择；旧 API 调用没有启用自动审核时保持原行为。
- 直接核验结果存为 `direct_verification`，后续路径存为 `reading_continuation`，其中保存原输入和原答指纹。之后的运行使用 `classic`，经过现有完整审核。最终结论不能计作“单次直答通过”。
- 同一个输入版本不会反复在两种路线之间循环。后续重读仍遵守已有次数限制和总调用额度。
- 已有证明、明确冲突、待答追问、待确认条件及显式本地核验模式，不触发这项自动继续。
- 手动选择沿用材料进入分阶段审核时，继承本次自动审核设置，保留同一份原材料。

## 文件内容

网页提交 `share_table_rows=true`。预览列明发送的完整内容；用户原有的发送许可同时涵盖读取和必要复核。补充表各工作表、所选观测数据表的数据行在各入口保持一致，数据仍由原文及来源审核判断属于总体信息还是有限样本。

API 可显式指定 `share_table_rows=false`，仅传递原有表结构和记录范围。未指定时保留旧接口行为：直答模式读取行，经典模式只读元数据。后台继续使用已经读取的 `case.sources`，不重新打开文件，也不扩大原发送范围。程序不会因为看到数字表就宣称它是精确总体信息。

总体均值 CSV 另附编码或时期说明时，后台使用原有 `network-information-evidence-review` 合同核对来源角色。模型明确指出哪一个原始文档包含表格、哪些文档仅提供说明；程序按现有来源定位逐项生成审核记录，原检查器仍要求来源无遗漏、无重叠且每个信息条目引用原表。第二张总体表或额外约束不得被归为说明。无法核实时保留具体问题或读取错误，科学条件仍单独确认。

## 输出要求

“只求公式”“不需要数值”等输出要求由研究问题和原材料保存。事实审核检查候选是否保留真实可用的总体算子、变量及覆盖范围，不要求在 `data_description` 再抄一遍这句话。

这不豁免科学内容：评价名单、时期、方向、采用态度、信息覆盖及额外限制仍须完整审核。仅说“求公式”不能让未知总体算子变为已提供；复核结果也不会被程序强制改为通过。
