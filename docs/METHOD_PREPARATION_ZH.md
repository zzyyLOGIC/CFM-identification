# 从研究属性准备候选方法

这里说明程序怎样准备方法，不把“准备了候选”当作“定理条件已经成立”。

```mermaid
flowchart LR
    A[已有读取合同与来源检查] --> B[同一研究的目标、信息和条件]
    B --> C[按属性准备候选方法与具体实现]
    C --> D[独立核对读取和科学条件]
    D --> E[原生方法检查支持与适用域]
    E --> F[公式、界限或停止原因]
    F --> G[按原协议核验证据]
    C -.记录依据与缺项.-> H[候选准备说明]
```

## 这次统一了什么

`cfm_id.method_preparation` 接收解析后的属性，复用原有准备规则：

| 需要决定的事 | 所用属性 | 不在此处判断的事 |
|---|---|---|
| 完整政策均值、均值签名政策是否进入候选 | 总体信息算子、暴露定义、均值充分性的采用状态与覆盖范围 | 正支持、科学条件是否真实、结论是否 POINT |
| 有限均值模型使用哪个求界实现 | 分配设计、暴露形式、数值或符号信息 | 是否允许补界、是否能忽略额外限制；完整模型检查仍由原合同负责 |
| DAG 哪些方法角色允许准备 | 明确指定／禁止的前门角色、指定调整集 | 后门、前门、调整集准则是否成立 |

其他明确目标继续使用现有公共目标与方法合同。例如观察性局部效应的平均方式对应关系由 `observational_methods` 和 `research_spec_observational_adapters` 共同维护；不再建一份重复表。单臂、有限政策分布、均值顺序以及各专用目标也保留其原准入检查。

本轮没有统一或放宽所有数学条件，没有按方法名称前缀进行判断，也没有添加“某方法失败就自动换模型求 PARTIAL”的规则。

## 八个共同读取入口使用同一种说明记录

`business_dispatch.inspect_methods` 在事实检查到达方法准备阶段后，附加 `method_preparation_report`。八个共同读取入口均使用此格式；前置来源审核尚未完成时，原有停止记录仍优先返回，不能假装已经检查过方法。

每份记录包括：

- 本次确实使用的读取入口、原计划绑定与整份计划摘要。
- 目标、设计、暴露、信息和科学声明在原计划中的位置；不另造一份目标。
- 本入口登记的每个候选：准备了什么、已有排除原因、尚待核对还是本次根本未检查。
- 候选使用的基础方法、目标操作与具体实现，以及原审核表的位置和原绑定。
- 两政策问题保留各端排除原因，不拿一端准备完成代替两端共同模型。

```python
from cfm_id import project
from cfm_id.method_matching import verify_report

report = project.explain_method_plan(plan, reader_id="NETWORK_FIXED_POLICY_FACTS")
assert verify_report(plan, report, reader_id="NETWORK_FIXED_POLICY_FACTS")
```

`verify_report` 仅检查说明与当前计划是否一致，**不是数学证书核验**。说明记录不能作为审核决定提交给执行器。

| 状态 | 含义 |
|---|---|
| `CANDIDATE_REQUIRES_REVIEW` | 已准备候选及审核表，仍需原审核和数学检查 |
| `DECLARATION_OR_INFORMATION_UNRESOLVED` | 原检查明确记录了尚未确定的声明／信息 |
| `EXCLUDED_BY_PREPARATION` | 按现有准备规则排除；保留原原因，不扩写成不可识别证明 |
| `ENDPOINT_PREPARATION_INCOMPLETE` | 两政策至少一端没有准备所需共同方法，具体原因见各端 |
| `PREPARATION_STOPPED` | 某专用投影没有形成完整可审核候选 |
| `NOT_ASSESSED` | 本次没有该方法的检查记录；不等于条件不成立 |

原审核表中网络与 DAG 的绑定格式不同，记录保留各自字段，不把它们硬改为同一种许可。

## 尚未统一的边界

默认直答核验、普通 ATE／Manski、一般图 ID、二元 IV 和上传数学规格仍有专用合同。它们已经存在的入口与证据继续有效，但不能宣称都经过这份共同候选准备记录。默认网页转入共同读取时会生成该记录；仅在直答核验阶段结束的任务仍使用原核验记录。

原生执行结果中的 `attempts` 说明数学检查实际发生了什么；本记录只说明准备阶段。四类原有详细方法诊断仍可结合真实审核和执行记录查看。后续按各专用合同接入说明，不复制求解器，不把图识别、工具变量与网络目标硬转为同一对象。

网页不增加用户确认步骤；记录随现有计划／结果下载。新增说明不参与原计划、审核或证书的哈希，旧证书不改写。计划被编辑后，旧说明也应重新生成。
