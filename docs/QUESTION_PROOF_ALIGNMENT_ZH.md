# 原问题、数学规格与结果如何保持一致

本说明对应默认入口和明确规格入口的交接检查。证书证明的是一份数学规格的结论；是否忠实于用户原问，还需要来源审核和字段转换检查。两者不能相互替代。

## 检查顺序

```mermaid
flowchart LR
  A[原问和附件] --> B[读取目标、资料与采用条件]
  B --> C[独立对照原文审核]
  C --> D[按原范围构造数学规格]
  D --> E[检查适用条件并执行原方法]
  E --> F[重放证书或见证]
  F --> G[核对状态、目标和转换记录]
  G --> H[显示结论并登记对应查询]
```

这张图是交接检查顺序，不是新的数学分类。原数学方法及 D/E 参数含义不变。

每一步都保留以下区别：

- **评价谁、何时、比较什么**：完整研究名单与评价子集、权重、先后两端、结果定义及编码、时期与固定背景。
- **条件适用于哪里**：采用、不采用、未决定分开；某些对象或安排的条件不得扩大为全部对象、全部安排。
- **资料实际提供什么**：总体律、总体均值、已给定的数值和有限样本不能互换；数据覆盖范围与科学前提分开记录。
- **实际证明了什么**：POINT、PARTIAL、不可点识别见证、条件不相容、入口未覆盖分别处理；模型原答不自动成为核验结论。

## 各入口实际负责的对应检查

| 入口 | 必须保留的内容 | 已有检查位置与边界 |
|---|---|---|
| 随机网络局部目标、直接/同伴/局部总效应 | 同一评价名单、两端顺序、时期、结果、暴露规则、完整分配律；不能把一类目标改算成另一类 | `network_source_alignment`、`network_query_exchange`；经典分阶段入口另有 `reviewed_intent_handoff` 和 `ordered_target_handoff`。不把边际概率当独立联合分配。 |
| 完整政策、签名政策和有限政策组合 | 每端完整安排、混合概率、评价权重、总体来源；充分性适用的对象与安排范围 | `network_existing_entry`、`method_preparation`；比较实际原生输入和结果的 study/target/source/assumptions。签名范围缺失不能默认全网、全安排。共同查询合并后精确消去零系数。 |
| 观察性网络的三种局部平均方式 | 原文选择的平均方式、背景、分层或局部特征、资料覆盖及各自所需条件 | `observational_effect_entry` 复用已有规划和原生接口；执行后比对 study/source/assumptions/signature/requests/license。不能改用更容易成功的平均方式。 |

上述入口可能复用同一方法。这张表是职责清单，不代表新增十个互斥类别，也不扩大数学支持范围。具体能力见 [默认入口清单](DEFAULT_ENTRY_INVENTORY_ZH.md)。

## 统一结果检查

`joint_natural_entry.replay` 在重新审核已保存来源、重建问题、执行原核验器后，还比较以下内容：

- 方法操作、问题规格、投影记录、所需条件和已确认记录；
- 外层完成状态、POINT/PARTIAL 等结论、实际原生结果和证书；
- 如有独立显示的答案，其目标和结论也须与重建结果相同。

重试日志和纯说明措辞不作为数学条件。网页在成功收件后设置的交接标记可以不同，但合成研究不能被标成真实研究的科学确认，也不授予生产准入。

估计接收端仍重新构造交接包，核对查询、系数及范围。不可识别见证虽然不交给估计，也要在显示前重放。核对失败时撤销该次运行的旧回执和旧结论，保留检查记录；不会要求用户凭空补一项科学条件来消除程序错误。

## 能保证与不能保证的内容

结构化字段正确且已审核时，可以检查它们是否原样、按正确方向和范围进入数学执行及查询交接。来源变更后，旧审核和旧证书不能继续授权新输入。

原句是否被模型正确理解仍是单独的问题。引用存在、哈希相同或数学证书通过，都不能单独证明自然语言理解正确；独立来源审核也不能承诺零误读。新任务或含糊范围仍须审核，真正缺失才追问；当前方法不能表达的已采用条件必须明确停止，不能删除后给出较弱问题的结论。
