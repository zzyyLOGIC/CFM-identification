# 网页与公共 API 的读取复核交接

页面负责收集输入和展示结果；识别执行仍由同一份库完成。更换布局时，不应另写一套研究语义或默认接受规则。

## 复核必须收到什么

1. 当前输入和来源目录，以及与它们绑定的完整读取候选。不能只传一个字段、遗漏其余字段已经保存的定义。
2. 生成这份候选时实际使用的 Prompt、Skill 和输出合同。字段说明由 `cfm_id_llm.review_schema_context.schema_contract` 解析，个人页和公共 API 共用；这些说明不是业务证据。
3. 必要重读时，上一轮复核具体反对的字段及原因。反馈仅适用于同一候选和来源，不自动批准、不替代新一轮来源核对。
4. 原文明确采用、不采用、尚未决定和真正额外限制的不同状态。科学条件继续由相应合同要求的研究者确认。

公共 API 的字段审核和重读可能分别用 `quote/source_id` 和 `text/doc_id` 表示同一个原文片段。恢复反馈应核对片段编号、所属文档及逐字内容，而不是把这两种展示格式的不同误判成材料变化。候选、文档、编号或原文变动后，旧反馈不能复用。

逐字段审核与错误定位必须使用同一份引用合同。事实取值正确但该记录漏引支持范围或定义的原文，仍属于需要重读的引用遗漏；不能因为完整材料里存在这句话就自动放行。共享定义仅在读取合同明确指定 owner 时复用，其他合同继续要求字段自身引用。定位后的候选仍须经过完整审核。

若第一次字段复核指出具体错误，允许对争议字段独立核对一次，完整候选、原文、来源绑定保持不变。第二次必须逐项给出判断与引用；空答、格式错误、额外诊断不能覆盖初次拒绝，未决定也不重复投票。两次记录均保留。这与个人页原有的定向复核一致，不代替科学条件确认。

来源分类只选择读取入口。实际随机抽签但概率规则尚缺时，保留“随机”的性质，同时让设计字段保持未知，追问具体规则。资料中的多个均值格子不等于多个业务问题。

直答请求也必须列出已接入的专用提示：网络局部目标的多问题、评价子群和非等权权重使用 `NETWORK_LOCAL_BUNDLE`。关系来自文字或文件不改变这一点。提示只触发独立的原文范围核对，不直接授予点识别或批准条件；随后每问分别保留名单、权重、比较方向及证书。

## 两处容易误解的兼容字段

- `outcome_kind=continuous` 在现有网络均值合同中是原始实值尺度的名称，不要求结果分布存在密度。数值评分也可以用这个实值域；二元、计数和未知类型分别保留。它不证明均值存在、不允许擅自给类别编码。
- 新的联合/局部目标读取请求只让模型选择实际存在的原文片段编号，由程序取回原句，避免重复抄写长表。历史带 `quote` 的答卷仍按原规则核查，错误引用仍拒绝；错误反馈保留编号和可执行说明，不静默替换错误引文。

联合/局部目标读取及其复核使用同一份引用类型，不继承普通 ATE 输入对模型短引文的 6000 字上限。程序取回的完整关系表可以更长，但仍必须满足来源存在、内容非空、逐字属于该来源的检查；不截短证据或跳过语义复核。

## 局部目标的条件范围

不同条件不能统一解释为“所有反事实安排下的性质”。局部目标合同保留已有 `all_assignments`，并允许原文明确给出下面三种对应范围；未提供新字段的旧答卷保持原绑定和原检查。

| 条件 | 对应范围 | 仍需核对 |
| --- | --- | --- |
| 一致性 | `OBSERVED_CONSISTENCY`：观察结果对应实际完整安排 | 原文适用对象、结果定义、时期；不能借用其他对象的声明 |
| 固定网络 | `FIXED_PRETREATMENT_NETWORK`：网络处理前确定、本期固定 | 完整网络范围和时期，不把动态或处理后网络当作固定网络 |
| 所需条件均值有限 | `TARGET_EVENT_MEANS`：明确哪些问题的各端条件均值有限 | `target_indices` 对应当前问题下标，必须覆盖各端及 `covered_nodes`；只覆盖另一问题或一端不能借用 |

新范围只由原文读取并经独立来源复核产生，之后仍须按合同确认科学条件。它们不能代替完整分配随机化或第一阶段排除限制。明确拒绝、未知对象范围、未覆盖的目标和额外限制继续阻断。原生数学方法、目标、公式和证书重放未改变。

## 页面显示

模型原答与数学库核验分别展示。模型文本中的公式做显示转换，原始文本继续保留；显示转换不计算答案、不授予识别或估计许可。没有通过核验时，不能把模型判断显示为库的结论。

长公式在公式区域内横向滚动，不能把整页撑宽；桌面并排和手机单列均需用实际多问题结果检查，不能只检查短公式。

后台复核未完成与用户确实缺材料要分开。前者保留材料并提供重试，技术表默认折叠；后者只问实际缺少的信息。研究者明确拒绝科学条件时保留拒绝结果。

## 验收和回退

比较新旧入口时，除业务问题外还要核对附件、提取后的材料、模型设置和读取合同是否相同。只比较同名示例的最终成功次数，不能说明是模型能力还是网页改造导致差异。

必要验收覆盖正常识别、部分识别、缺项补充后继续、拒绝所需条件和额外限制。真实模型新读取与封存答卷重放分别报告；反复修复后的成功不能称作首答正确率。

新版独立运行并保留旧版本。部署前记录源码版本与启动方式；旧任务跨版本能否续跑以其绑定检查为准，不修改旧证据以迁就新源码。
