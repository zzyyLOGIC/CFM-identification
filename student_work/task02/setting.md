# 任务 02 —— setting、support 与点识别论证

**分配到的任务：** 任务 02 = **D1 × E2**
**Setting 编号：** D1（每人概率不同的独立伯努利分配）× E2（三档被处理邻居占比）

---

## 1. 业务场景

一家公司给共享客户线索的销售员开放 AI 销售助手。一名销售员的业绩同时取决于**两件事**：
**自己**有没有助手 `T_i`，以及**与他合作的同事中有多少人也在用**——也就是他的**暴露**。

合作关系在开放之前就**已经固定**，用网络 `G = (V, A)` 表示，当 i 与 j 有合作时 `A_ij = 1`。
它与处理前协变量 `X` 一起被视为"给定"：只会出现在条件符号的右边，我们不需要它们的数值。
因此可观测的总体分布是 `P(T, Y_obs | A, X)`。

---

## 2. 相对共享 baseline，我改了什么

| 组成 | 共享 baseline | **本任务（02）** |
|---|---|---|
| 分配 `D` | 所有人 iid `Bernoulli(1/2)` | **D1：** `T_i ~ Bernoulli(p_i)`，各人独立，`0 < p_i < 1`，`p_i` 处理前已知 |
| 暴露 `E` | 严格多数 `S_i = 1{K_i > ⌊d_i/2⌋}`（两档） | **E2：** `E_i = K_i / d_i`，分**三档** |
| 每人 arm 数 | 4 | **6**（`t ∈ {0,1}` × `s ∈ {0,1,2}`）；`N = 300` 时共 `6N = 1800` 个 arm mean |
| `K_i` 的分布 | 二项分布 | **泊松二项分布** |
| 效应对比 | 同 baseline | **在本 setting 中重新定义**（见 §6） |

其余部分原样继承：网络处理前固定，一致性（consistency）、整体随机化（full-vector randomization）、
目标量以及 support 的定义都不变。

### 2.1 分配规则（D1）

```
T_i ~ Bernoulli(p_i)，各人独立，0 < p_i < 1，p_i 在处理前已知
q(u) = P(T = u | A, X) = ∏_j p_j^{u_j} (1 − p_j)^{1 − u_j}
```

因此任意一个人的自身处理概率是 `P(T_i = t) = t·p_i + (1 − t)(1 − p_i)`。
演示中取 `p_i ~ Uniform(0.2, 0.8)`（固定随机种子）；设计本身只要求 `0 < p_i < 1`，
所以具体取值是本 setting 自己声明的设计选择。

### 2.2 暴露定义（E2）

```
K_i(u) = Σ_{j ∈ N(i)} u_j   （被处理的邻居数）      E_i(u) = K_i(u) / d_i   （需要 d_i ≥ 1）

S_i(u) = 0  若 E_i(u) < 1/3      1  若 1/3 ≤ E_i(u) < 2/3      2  若 E_i(u) ≥ 2/3
```

因为 `K_i` 是整数，两条实数分界线必须先换算成整数区间。设 `k1 = ⌈d/3⌉`、`k2 = ⌈2d/3⌉`：

| 档位 `s` | 含义 | `K_i` 区间 |
|---|---|---|
| 0 | 低 | `[0, k1 − 1]` |
| 1 | 中 | `[k1, k2 − 1]` |
| 2 | 高 | `[k2, d]` |

算例：`d = 1 → (k1, k2) = (1, 1)`，得到 `[0,0] / [1,0] / [1,1]`——**中间档区间为空**；
`d = 2 → (1,2)` 得到 `[0,0] / [1,1] / [2,2]`；`d = 3 → (1,2)` 得到 `[0,0] / [1,1] / [2,3]`。

---

## 3. 目标量

设计标准化的 arm mean，即任务书式(1) 的形式：

```
μ_i(t, s) = E_design[ Y_i(t, T_-i) | S_i(t, T_-i) = s, A, X ]
          = Σ_{u : u_i = t, S_i(u) = s} w(u) · Y_i(u),
   w(u) = q(u) / π_i(t, s),    π_i(t, s) = P(T_i = t, S_i = s | A, X)
```

这里 `S_i` 只用作**目标标准化的分组**，并不断言结果机制只通过 `S_i` 依赖邻居。

---

## 4. 三个假设（缺一不可）

1. **一致性（consistency）**——若实际分配为 `u`，则 `Y_obs_i = Y_i(u)`。
2. **整体随机化（full-vector randomization）**——给定 `A, X` 时，整个分配向量 `T` 与全部潜在结果
   `{Y_i(u)}` 独立。这一条来自实验协议，不需要用数据检验。
3. **该查询的正总体支撑（positive population support）**——所查询的 arm 满足 `π_i(t, s) > 0`。

E2 带来的边界条件：当 `d_i = 0` 时 `S_i` 没有定义。因此孤立节点**不在 E2 的适用范围内**，
声明为**不适用**，而不是给它指派一个档位。共享的固定 ER300 网络中没有孤立节点；
如果传入孤立节点，`support.py` 会抛出 `UndefinedExposureError`。

---

## 5. 总体支撑概率，以及为什么有支撑的 arm 是 POINT

**支撑概率。** 在 D1 下各人的处理指示变量互相独立，且 `i ∉ N(i)`，所以 `T_i` 与 `S_i` 独立，
支撑概率可以拆成两项相乘：

```
π_i(t, s) = P(T_i = t) · P(S_i = s)
          = [ t·p_i + (1 − t)(1 − p_i) ] · Σ_{k ∈ R_s(d_i)} P(K_i = k)
```

其中 `R_s(d_i)` 是 §2.2 给出的整数区间，`P(K_i = k)` 是 `d_i` 个独立 `Bernoulli(p_j)`（`j ∈ N(i)`）
之和的泊松二项分布，由 `support.py` 中的 `poisson_binomial_pmf` 用 `O(d²)` 动态规划精确计算。
自己的 `p_i` 只出现在第一个因子里；泊松二项只用邻居的 `p_j`。

**哪些 arm 真的存在**（是算出来的，不是断言的）：因为 `0 < p_j < 1`，每个 `k ∈ {0, …, d_i}` 都有
严格正的概率；又因为 `0 < p_i < 1`，自己的两种处理取值都可能。于是

```
π_i(t, s) > 0   ⟺   R_s(d_i) 非空
```

* `d_i ≥ 2`——三个区间都非空：**6 个 arm 全部有支撑**；
* `d_i = 1`——`R_1(1) = [1, 0] = ∅`：两个 **medium** arm `(0,1)` 与 `(1,1)` 的 `π = 0`，
  其余 4 个 arm 有支撑；
* `d_i = 0`——E2 未定义，按 §4 作为**不适用**处理。

这是关于**总体设计**的陈述，不是关于有限样本的：某一次实验中某个格子恰好没出现，并不改变
POINT 的性质。

**POINT。** 取任意满足 `π_i(t, s) > 0` 的 `(i, t, s)`，把条件事件按它包含的分配向量拆开，
再代入随机化与一致性（任务书第 3 节的两步）：

```
E[Y_obs_i | A, X, T_i = t, S_i = s]
  = Σ_{u_-i : S_i((t, u_-i)) = s} E[Y_obs_i | A, X, T = (t, u_-i)] · w(u_-i)   （全概率公式）
  = Σ_{u_-i : S_i((t, u_-i)) = s} E[Y_i((t, u_-i)) | A, X] · w(u_-i)          （随机化 + 一致性）
  = μ_i(t, s)                                                                （目标量的定义）
```

其中 `w(u_-i) = q((t, u_-i)) / π_i(t, s)`，完全由已知的分配规则和 `π_i(t, s)` 决定。
右边每一项都是总体可观测分布 `P(T, Y_obs | A, X)` 的泛函，所以观测分布相同的两个世界必然一致：

```
μ_i(t, s) = E[ Y_obs_i | A, X, T_i = t, S_i = s ]        （式 3）      →  POINT
```

整个推导没有用到结果机制、估计阶段或模拟器的任何信息。

**若 `π_i(t, s) = 0`：** 条件事件 `{T_i = t, S_i = s}` 的概率为零，因此式(3) 右边的条件期望
**没有定义**——不是 0，不是 NaN，而是不存在。所以式(3) 不能使用，`rule.py` 会拒绝该查询
（抛出 `ZeroSupportRefusal`），而不是返回一个数值。假设未确认时同样拒绝，绝不会悄悄给出 PARTIAL 结论。

## 6. 本 setting 声明的效应对比

任务书只针对两档暴露的 baseline 定义了 `τ^Direct`、`τ^Spillover`、`τ^Total`。在三档下，
这必须由我们自己明确声明。我们固定使用低档和高档，使任何对比都不会碰到那个可能无支撑的 medium 档：

```
τ_i^Direct    = μ_i(1, 0) − μ_i(0, 0)     暴露固定在低档，只比较自身处理
τ_i^Spillover = μ_i(1, 2) − μ_i(1, 0)     自身处理固定为 1，暴露由低到高
τ_i^Total     = μ_i(1, 2) − μ_i(0, 0)     从（无助手、低暴露）到（有助手、高暴露）
```

当 `d_i ≥ 2` 时，上式每一项都有支撑；当 `d_i = 1` 时，这三个对比依然成立（涉及的 4 个 arm 都有支撑），
但任何用到 `s = 1` 的对比都必须拒绝。

## 7. 验证与范围

* `test_rule.py::test_brute_force_matches_closed_form` 在 `n ≤ 8` 的小图上枚举**全部** `2^n` 个
  分配向量，按定义直接数出 `π_i(t, s)`，与 `support.py` 的结果比对到 `1e-12`。
* `test_rule.py::test_poisson_binomial_equals_binomial` 在所有 `p_j` 相等时把 PMF 退化成精确二项分布，
  用来检查动态规划是否写对。
* 正常例、零支撑例、非法参数例、孤立节点例，以及 `rule.py` 的拒绝行为都分别有覆盖。
* `demo.ipynb` 在共享的固定 ER300 网络外加一张手工小图（含一个度数为 1 的节点）上，
  跑通完整链条——业务问题 → setting → support → POINT 论证 → `IdentificationResult`。

已知局限：只处理 D1 × E2，不尝试任何通用的 design / exposure / support 框架，这与任务书和
`CONTRIBUTING.md` 的要求一致。`X` 从不参与数值计算。support 是在总体设计层面精确计算的；
有限样本的不确定性属于 Estimation 阶段。`d_i = 0` 的节点声明为**不适用**，而不是指派档位。
