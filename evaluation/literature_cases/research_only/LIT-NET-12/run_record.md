## 数值复核

甲组四人两两相连（六条边），乙组为链 学7—学5—学6—学8（三条边）。方案 A 每组一名带学人（学1、学5），方案 B 每组两名（学1、学2、学5、学6）。

方案 A：

- 学3 相邻学1、学2、学4，其中只有学1 带学，相邻带学人一名，+0.053；
- 学4 情形相同，+0.053；
- 学7 只相邻学5，+0.082；
- 学8 只相邻学6，学6 这次不带学，为 0；
- 学1、学2、学5、学6 为高表达能力同学，成绩不变，为 0；
- 合计 0.188，即 47/250；平均 0.0235。

方案 B：

- 学3 相邻学1、学2、学4，其中学1 与学2 都带学，相邻带学人两名，−0.061；
- 学4 情形相同，−0.061；
- 学7 仍 +0.082，学8 这次相邻的学6 带学，+0.082；
- 学1、学2、学5、学6 为 0；
- 合计 0.042，即 21/500；平均 0.00525。

随机政策与目标：

- Target = 1/2×0.0235 + 1/2×0.00525 = 0.014375，即 23/1600；
- 两方案均值之差 0.01825，属加派带学人的边际效果，不是目标量；
- 甲组合计 0.106 与 −0.122，符号反转；乙组合计 0.082 与 0.164，只升不降；同一套加派动作在两种结构里的效果形状不同，说明结构差进入了答案；
- 目标变化版（学3、学4，各 1/2）：1/2×0.053 + 1/2×(−0.061) = −0.004，即 −1/250。

中间值只有四位小数，没有近似替代；本题两套名单的均值都是有限小数，不涉及舍入误差。

## 引擎输出与手算的关系

`result.json` 的 `numeric_value` 为空，这是框架的统一行为：POINT 表示识别出可点识别的泛函，数值留给 estimation 阶段，`estimation_handoff_allowed` 为 false。上面 23/1600 与 −1/250 是对该泛函的独立手算复核，不是引擎输出。LIT-NET-09、10、11 同样如此。

引擎侧核对到的结构：原题 population 为八名同学、权重各 1/8、两套政策分别为 `[1,0,0,0,1,0,0,0]` 与 `[1,1,0,0,1,1,0,0]`、权重各 1/2、目标类型 `FINITE_POLICY_MEAN`；目标变化版 population 为学3与学4、权重各 1/2、政策不变。

## 与 LIT-NET-09 的结构关系
