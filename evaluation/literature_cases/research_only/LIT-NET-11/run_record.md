## 数值复核

组内每十家两两可交流，组间无连接。方案 A 每组前五家被直接告知，方案 B 每组前八家。

同行业组（组一、组二）未被直接告知者的申请概率：0.291 − 0.212 = 0.079。
混合行业组（组三、组四）未被直接告知者的申请概率：0.291。

- 方案 A，同行业组每家：0.5×0.300 + 0.5×0.079 = 0.1895，即 379/2000；
- 方案 A，混合行业组每家：0.5×0.300 + 0.5×0.291 = 0.2955，即 591/2000；
- 方案 A，四十家均值：(0.1895 + 0.2955)/2 = 0.2425，即 97/400；
- 方案 B，同行业组每家：0.8×0.300 + 0.2×0.079 = 0.2558，即 1279/5000；
- 方案 B，混合行业组每家：0.8×0.300 + 0.2×0.291 = 0.2982，即 1491/5000；
- 方案 B，四十家均值：(0.2558 + 0.2982)/2 = 0.277，即 277/1000；
- 随机政策均值：1/2×0.2425 + 1/2×0.277 = 0.25975，即 1039/4000；
- 两方案之差：0.277 − 0.2425 = 0.0345，即 69/2000，属政策含义，不是目标量；
- 目标变化版（同行业两组二十家）：1/2×0.1895 + 1/2×0.2558 = 0.22265，即 4453/20000。

中间值一律保留四位小数，未作近似替代。若按两位小数取 0.19 与 0.26 再平均，会得到 0.223，与精确值差 0.00035，因此目标变化版必须用四位小数的中间值。

## 引擎输出与手算的关系

`result.json` 的 `numeric_value` 为空，这是框架的统一行为：POINT 表示识别出可点识别的泛函，数值留给 estimation 阶段，`estimation_handoff_allowed` 为 false。上面 0.25975 与 0.22265 是对该泛函的独立手算复核，不是引擎输出。LIT-NET-09 与 LIT-NET-10 同样如此。

引擎侧核对到的结构：原题 population 为四十家、权重各 1/40、两套名单分别处理二十家与三十二家、权重各 1/2；目标变化版 population 为二十家、权重各 1/20、政策不变。
